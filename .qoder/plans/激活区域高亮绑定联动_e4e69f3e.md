# 激活区域↔进度轴高亮↔图片浏览页 三向联动

## 已确认的设计决策
1. 绑定模型：手动显式绑定（在 `HandlePair` 上维护高亮引用列表）
2. 栏目位置：主窗口 `timeline` 页底部新增"第三区"
3. 添加交互：popover 列出全相册中"未被该激活区域绑定"的高亮供勾选
4. 跳转深度：仅切 `main_stack` 到 album 页 + `album_set_active`，并在进度轴上把被点击的高亮突出渲染作为视觉反馈

## Task 2: HandlePair 增加绑定列表（仅存 hl_id，免受页/层下标漂移影响）

文件 [album.h](file:///home/admin01/notework/src/album.h) 与 [album_model.c](file:///home/admin01/notework/src/album_model.c)：

- `HandlePair` 增加 `GArray *bindings;`（元素类型 `guint64`，按值存 hl_id；可能为 NULL）
  关键设计：**只存 `hl_id`，不存 page_idx/layer_idx/rec_idx**。`hl_id` 全局单调递增唯一，能彻底消除页面增删/移动、图层增删/移动、记录顺序变化导致的引用漂移问题；定位时统一通过 `album_find_highlight_by_id` 反查。
- 新 API：
  - `album_pair_bind_highlight(Album*, int track_idx, int pair_idx, guint64 hl_id)` → 幂等添加（已存在则跳过）
  - `album_pair_unbind_highlight(Album*, int track_idx, int pair_idx, guint64 hl_id)` → 按 id 移除
  - `album_pair_clear_bindings(Album*, int track_idx, int pair_idx)` → 清空（供"清空"按钮使用）
  - `album_pair_get_bindings(Album*, int track_idx, int pair_idx)` → 借用返回 GArray<guint64>（可空）
  - `album_pair_has_binding(...)` → 包含查询
- `album_track_clear` / `album_track_remove_pair` 中遍历释放每个 pair 的 bindings GArray
- 新增 `gboolean album_find_highlight_by_id(Album*, guint64 hl_id, int *out_page, int *out_layer, int *out_rec)` → 全局查找（用于栏目展示、跳转、懒清理时校验存活）

## Task 5: main.c 集成栏目逻辑与三向联动

文件 [main.c](file:///home/admin01/notework/src/main.c)：

- `AppView` 新增字段：`int sel_track_idx; int sel_pair_idx; GtkWidget *bindings_title; GtkWidget *bindings_list; GtkButton *bindings_add_btn; GtkButton *bindings_clear_btn; AdwViewStack *main_stack;`
- 注册全局回调 `on_pair_selected(track_idx, pair_idx, AppView*)`：更新 `sel_*`，调 `refresh_bindings_panel(v)`
- `populate_tracks` 中将 `on_pair_selected` 通过 setter 注入到每个 `track_row_new` 创建的 bar；并把 `sel_*` 同步给对应 bar 的 `track_row_set_selected_pair` 让选中态视觉持久
- `on_album_changed` 入口先做有效性校验：若 `sel_track_idx` 越界或对应 pair 越界，直接清空 `sel_*`；末尾必调 `refresh_bindings_panel` 与进度轴 emph 重算（懒清理在此触发）
- 新函数 `refresh_bindings_panel(AppView *v)`：
  1. 若 `sel_track_idx<0` → 标题置 "未选中激活区域"，listbox 清空，`bindings_add_btn`/`bindings_clear_btn` 置灰（`gtk_widget_set_sensitive(FALSE)`），`progress_axis_clear_emphasized`，return
  2. 否则取该 pair 的 bindings 数组，**就地懒清理**：遍历副本，调 `album_find_highlight_by_id` 反查；找不到的 hl_id 调 `album_pair_unbind_highlight` 剔除
  3. 用清理后的 bindings 重建 listbox：每行行内容"P{page+1} · 层{layer} · 记录 #{rec_idx+1}"+ 跳转按钮 + 删除按钮
     - 跳转按钮：`adw_view_stack_set_visible_child_name(main_stack,"album")` + `album_set_active(album, page_idx)` + 触发 `on_album_changed` 让 album_view 刷新 + `progress_axis_set_focused_highlight(pa, page, hl_id)` + 进度轴 queue_draw
     - 删除按钮：`album_pair_unbind_highlight` + 重新刷新栏目 + 进度轴 queue_draw
  4. 末尾把当前 bindings 拷贝成 GArray<{page,id}>（每条用 `album_find_highlight_by_id` 解析）调 `progress_axis_set_emphasized` 进度轴 queue_draw
  5. 两个按钮恢复 sensitive=TRUE
- "+ 添加"按钮回调 `on_bindings_add_clicked`（仅在 `sel_*` 合法时触发；不合法时按钮已灰）：弹 GtkPopover
  - 扫描全相册所有 LAYER_HIGHLIGHT 中的记录，过滤掉"已被该 pair 绑定（hl_id 包含查询）"的，构造勾选列表（GtkCheckButton 行："P{page+1} · 层{layer} · 记录 #{i+1}"）
  - 列表为空时 popover 内显示一行说明文本"没有可添加的高亮记录（请先到画布画一些高亮）"
  - 底部"确定"按钮：一次性对所有勾选项 `album_pair_bind_highlight` → 关闭 popover → `refresh_bindings_panel`
- "清空"按钮回调：`album_pair_clear_bindings` → `refresh_bindings_panel`

## Task 9: 边界情况与级联清理（统一懒清理策略）

所有失效场景一律采用**懒清理**：失效时不主动扫描整个 album，而是在「刷新栏目」与「进度轴 emph 渲染」时按 `hl_id` 反查，找不到就剔除。具体覆盖：

| 场景 | 触发点 | 处理 |
|---|---|---|
| 用户在 doodle 画布删除某条高亮 | doodle_canvas 内部高亮删除路径 | 不改 doodle_canvas；下次 `on_album_changed` → `refresh_bindings_panel` 反查时剔除 |
| 用户在 album_window 删除整张 LAYER_HIGHLIGHT 图层 | album_window 图层删除按钮 | 同上：失效 hl_id 反查不到，懒剔除 |
| 删除整页 (`album_remove_page`) | 既有 API | 同上；page 移动 (`album_move_page`) 因不存 page_idx 自然不受影响 |
| 删除整条轨道 (`album_track_remove`) | track_row 侧栏删除按钮 | `album_track_clear` 中链式释放该轨道下所有 pair 的 bindings GArray；main.c 在 `on_album_changed` 中检测 `sel_track_idx` 越界 → 清空 `sel_*` |
| 删除某 pair（drag-end 零宽 / 选中后另增 "删除该激活区域" 入口；本期保留现有零宽删除即可） | track_row 内部 | `album_track_remove_pair` 中释放该 pair 的 bindings；main.c 检测 `sel_pair_idx` 越界 → 清空 |
| 选中的 pair 被并发删除时 popover 已弹出 | 极端时序 | popover 的 "确定" 回调先校验 `sel_*` 仍合法，否则静默关闭 |
| 跳转/进度轴点击命中后该高亮被并发删除 | 极端时序 | `pick_highlight_at_px` 命中后再调 `album_find_highlight_by_id` 复核；找不到则忽略本次跳转 |
| 复制图层 | 现有规则"跨页复制不复制 LAYER_HIGHLIGHT"已规避；任何 highlight_record_clone 副本都分配新 hl_id（Task 1） | 副本不继承绑定，与直觉一致 |
| 未选中 pair 时按钮 | UX | `bindings_add_btn` / `bindings_clear_btn` 灰显（Task 5 已含） |

### 数据一致性约束
1. **bindings 仅存 hl_id**：page_idx/layer_idx/rec_idx 全部不存（Task 2 已修正）
2. **`album_track_clear` / `album_track_remove_pair` 必须显式释放 pair->bindings**：避免内存泄漏
3. **`refresh_bindings_panel` 在第 2 步原地剔除失效 id 后再渲染**：用户能直接看到一致的列表
4. **进度轴 `set_emphasized` 接收的 emph_keys 在 main.c 端用反查后的 (page,id) 构造**：进度轴本身无需关心 hl_id 是否仍存活

## Task 10: 构建与冒烟

- `meson compile -C build`
- 手动验证：
  1. 导入 1-2 张图，画几条手绘+几条高亮
  2. 在 timeline 页拖出 1 个激活区域 → 单击它 → 标题更新、列表为空、"+ 添加"可弹 popover 列出所有高亮
  3. 勾选两条 → 列表显示两行，进度轴对应两段变橙色
  4. 删除其中一条 → 进度轴对应一段恢复
  5. 点击进度轴上某条高亮（橙色或黄色） → 主窗口切到 album 页且当前页变为该高亮所在页，进度轴该条加红描边
  6. 切换激活区域选中 → 列表与进度轴突出实时切换
  7. **边界回归**：
     - 在 doodle 画布删除一条已被绑定的高亮 → 回到 timeline 页选中该激活区域 → 列表中该条自动消失（懒清理）、进度轴 emph 也少一段
     - 删除整页 / 移动页面顺序 → 绑定关系仍正确指向原高亮（hl_id 不变）
     - 删除整条轨道 → main.c 不崩溃，sel_* 自动清空，栏目回到"未选中"
     - 未选中 pair 时"+ 添加"/"清空"按钮均灰显
